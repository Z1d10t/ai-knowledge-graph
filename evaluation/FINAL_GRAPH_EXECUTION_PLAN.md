# 材料专业术语知识图谱｜最后一轮执行方案

本轮交付目标是 **一份全库三元组数据、一张覆盖 285 篇论文的交互式大图、一张可放进汇报的总览图**。大图应允许从专业术语或别名进入，沿材料、结构、工艺、性能、机理和器件之间的关系浏览，并展开论文证据。

最短路径是先完成从已有 v3 到大图的统一导出，再离线补齐现有术语和观测。新一轮模型调用、学科本体扩建和全库质量评估都移到交付后。下面的代码改动、命令及验收条件可直接交给实施者。

## 3. 先打通统一导出脚本

### 3.1 输入与字段映射

导出脚本接受 `--input-dir`、`--papers-dir` 和 `--output-dir`。默认读 v3 目录，论文 Markdown 在项目父目录的 `材料论文/全部_285篇/md/`。加载顺序如下。

1. 逐行读取 `concepts.jsonl` 和 `instances.jsonl`，用原有 `concept_id`、`instance_id` 建节点索引。节点显示规范名或实例原名，保留类型、质量标记、别名、论文数和实例归属。
2. 逐行读取 `relations.jsonl`，校验每条 `relation_id` 唯一、两个端点均可解析。三元组用规范化的 `subject_label → predicate → object_label`，标识使用两端稳定 ID。实例 ID 保留论文作用域。按 `paper_id + relation_id` 固定排序。
3. 构建邻接索引和别名索引。搜索顺序设为 ID 或完整名称、精确别名、前缀、子串。支持英文、缩写、希腊字母和中文建议标签。歧义别名列出多候选及类型和论文，保留原化学式。大小写折叠仅用于搜索候选，节点身份继续使用 v3 ID。
4. `evidence_all` 随原关系保存。浏览器初始化只载简短标签、端点、谓词族、论文和状态。详细证据按论文拆成 JSON，需要时再加载。对有效行号展示论文标题、`paper_id`、原始行号、引文和上下文。附带完整原文时用相对链接。可移交包至少要保留可读的证据摘录及原文定位信息。
5. 输出到指定目录。重复执行时先在同父目录 staging 写完整结果，检查通过后发布到新版本目录。目录已存在时要求显式授权覆盖或选择新目录，避免半成品混进现有交付包。

### 3.2 固定交付文件

| 路径，相对于输出目录 | 用途 |

| `triples_full.jsonl` | 同批关系结构化导出，完整保留证据列表及来源字段 |

CSV 至少保留以下字段，JSONL 同步保留全部原始信息。

~~~text
relation_id,subject_id,subject,predicate,object_id,object,
subject_type,object_type,family,paper_id,evidence_line,evidence,
evidence_text_match,direction_ok,polarity,modality,review_status,source
~~~

可额外输出 GEXF 供 Gephi 导入。只在主页面和三元组文件完成后做，其节点 ID、边 ID 和记录计数要与全量导出一致。

## 4. 一张大图怎样做到全、快、可读

### 4.1 同一个页面提供三个视图

| 视图 | 显示内容 | 操作 |
|---|---|---|
| **全库总览，默认打开** | 按概念类型汇总，例如材料、结构、工艺、性能、器件、表征、机理及缺陷。类型之间的连线粗细代表关系量，节点或边上展示汇总数。每个类别列出少量代表术语。 | 点击类别或连线进入该范围，按谓词族和论文继续缩小。总览统计覆盖整个数据集，图例注明汇总单元。 |
| **术语邻域** | 查到一个术语后显示其真实一跳三元组。默认可先绘制约 150 个相邻节点或 300 条关系，显示当前绘制量和匹配总量。 | 可逐批展开，也可沿任意邻接术语继续浏览。按方向、类型、谓词族、论文过滤。点边在侧栏看有方向的三元组、证据以及来源论文。 |
| **全部关系画布** | 显式切换后，把当前筛选条件下的真实节点和关系绘制出来。清除全部筛选并开启异常记录后，可以浏览整个已交付的关系集合。 | 全图用固定坐标，关闭物理模拟、平滑曲线和自动全量标签。默认按缩放级别显示标签并支持暂停分批绘制。全图缩放、搜索定位和点击展开证据使用同一份数据。 |

在首页显眼处放置「术语搜索」「全库总览」「全部关系」「下载三元组」。图例用类型着色，箭头在邻域或放大后显示。总览跨类边可以聚合，多篇证据的同向关系可以折叠，点开后保留各自原记录。全量 CSV/JSONL 必须包括所有输入关系及状态。默认邻域可隐藏方向异常行，提供可见开关，并给被标记边明确的复核状态。无行号的证据显示原引文和论文并标注定位缺失。

### 4.2 性能实现

- 后端导出时一次生成节点坐标。可先按类型分区，区内按连通分量、度数和稳定 ID 排序，用确定性网格坐标。总览可以用固定位置绘制十余个类型节点。两次构建在数据不变时节点位置相同。
- 页面用仓库内置 vis-network Canvas。邻域交互沿用 vis-network 选择事件。全图绘制用固定布局、小点、细线、无物理模拟，按批次插入数据集。开启全图时只载简明关系投影，证据文本留在分片里。
- 若目标机器浏览 4 万条边卡顿，在同一全图视图使用 Canvas 画预布局节点和边，按边范围与当前视口分块绘制，支持暂停和继续。可以优先画可见区并交替补画其它区域。全量导出保留每条边，页面显式报告绘制进度。交付版至少要保证总览、查询和邻域可以流畅使用。
- 页面打开后不依赖网络资源。证据、标签以文本方式渲染，避免把原文片段当 HTML 执行。大图入口通过本地 HTTP 加载分片文件。交付附一条点击即能运行的启动命令或 PowerShell 脚本。

## 5. 最终版本可加入的两项离线修复

### 5.1 挽回已经抽到的术语

已有 12 个定向补抽文件保存 **674 条术语条目和 402 条关系**。当前 `normalize_v3.py` 只遍历这些文件的 `triples`。在同一循环中加 `terms` 入口，先校验术语确实在该论文出现，再交给现有概念注册器，并独立记录其提及和证据。术语字段建议包括规范名、原文名、类型、别名、论文、段落或行号。术语可没有关联边。补抽条目历经去重、别名合并和证据校验，674 是输入数，新增节点数按实际计算。

- 复用已有 `ConceptRegistry`、证据定位器和论文内缩写作用域。仅接受正文明确给出的展开或已验证别名，化学式大小写和晶相使用现有 ID 规则谨慎处理。
- 日志输出 accepted / merged / rejected 及原因，保存术语来源行。来源定位可从该条原文证据计算，定位不到时进入复核队列。
- 回归选一条已有术语文件中无关系端点的可验证条目，确认导出主表可搜、术语卡片有来源。

### 5.2 恢复观测的值、单位和归属

当前 v3 的 16,829 条观测中，`value`、`unit`、`sample_id`、`conditions` 都为空。v2 将这些信息写在「材料或器件 → has measurement → 观测 ID」边上，v3 读取的是「观测 ID → measures → 属性」边。为每篇论文先按 `(paper_id, observation_id)` 索引两个方向的边，再组装一条记录。

- 从前一侧恢复 `owner_id` 或原样标签、`value`、`value_raw`、`unit`、`range`、比较符/不确定性、`sample_id`、`conditions`、数值类型和原证据。
- 从后一侧取得属性概念及补充证据。读取字段时用显式空值判断，保留数值 0。未匹配的观测保留记录并计数，已有真实条件数要与 v2 的 **6,430** 对账。
- 大图主线继续显示术语和关系，观测放在样品、器件或属性侧栏。只有明确可绑定到稳定 ID 的观测才进入按节点过滤的结果，避免把具体器件的成绩显示成材料通用性能。

两个修复和出图入口可独立完成。时间吃紧时优先从原 v3 出图，观测页使用已确认字段并在说明中标注缺失。各修订生成新目录，原 v2 与 v3 可随时回溯。

## 6. 实施完成后运行的命令

以下命令中的导出脚本、`--output-dir` 和 `--verify-only` 是本方案明确要实现的入口。仓库当前已有 `normalize_v3.py`，后者需要新增参数。所有命令从仓库根目录执行。

~~~powershell
# 先用冻结 v3 直接生成一份完整交付，确认先有可打开的图
python article/export_materials_graph.py --input-dir evaluation/full_v3_normalized --papers-dir "../材料论文/全部_285篇/md" --output-dir delivery/materials_kg_baseline

# 若两项离线修复完成，生成带修复的规范图谱和最终交付包
python evaluation/normalize_v3.py --output-dir evaluation/full_v3_delivery
python article/export_materials_graph.py --input-dir evaluation/full_v3_delivery --papers-dir "../材料论文/全部_285篇/md" --output-dir delivery/materials_kg_final

# 核对准备交付的目录。若交付基线版本就改成对应基线路径
python article/export_materials_graph.py --verify-only --output-dir delivery/materials_kg_final

# 本机打开交互大图
python -m http.server 8766 --bind 127.0.0.1 --directory delivery/materials_kg_final
~~~

浏览器打开 `http://127.0.0.1:8766/`。在全库总览导出 PNG，再从同一目录打包 HTML、资源、CSV、JSONL、PNG 和打开说明。基线版本交付时，让 ZIP 名称和报告明确使用基线版本号。

## 7. 交付验收清单

1. **全量守恒。** 最终主表的 CSV 数据行、JSONL 记录数、去重后唯一 `relation_id` 数完全一致，覆盖 285 篇，关系端点缺失数为 0。基线关系数等于 39,400。修订版逐项列出新增、合并和异常计数。样品实例不跨论文共用 ID。
2. **能看全图。** 打开首页能看到全库总览、清楚的图例及数据总数。切换全部关系画布可搜索与移动，筛选后绘制数随之变化，展开后能查到真实三元组。总览 PNG 能独立打开，标注论文数、真实关系数及类型汇总口径。
3. **能按专业术语定位证据。** 搜 `ALD`、`4Cl-BZS`、`α-FAPbI3`、`AgBiS2`。打开术语卡，检查别名、关系箭头、论文编号和引用行。核对 `α-FAPbI3` 与 `δ-FAPbI3` 没有混成同一节点。挑一篇综述看转引归属，挑一条异常边看开关及标记。
4. **交付包可移交。** 从最终 ZIP 解压到新目录启动一次，确认页面资源、搜索、证据分片和导出链接均可访问。目标机器上记录首页打开和搜索是否顺畅。把实际版本和剩余问题写进 README。
5. **准确描述验收性质。** 已有 10/10 固定检索用例可作回归。这里是交付验收，报告使用可核对的文件数、端点完整性和定位案例。独立论文评估、证据语义准确率和全库召回率留待后续单独测量。

## 8. 只有一轮时如何取舍

**第一优先级：统一导出，打开全库大图，点一条边能看到原文证据。** 先用冻结 v3 把这条路径做完，拿到当天可交付的结果。

**第二优先级：接入已有术语和修复观测。** 两项都来自本地缓存和现有 v2 输出，成本低于重抽正文。修好后换输入目录即可导出新版。

**留待之后：** 普通入口的完整术语双路重构、疑似摘要误删及失败块补抽、全量推断与跨学科本体扩展。尤其避免在交付当天改抽取提示词并重跑 285 篇，现有关系与证据已经足以生成正式的全库交互交付。
