# 05 术语与图谱模块

本文覆盖“从原始词到规范概念，再到检索、页面和导出”的模块。

## 1. `terminology.py` — 术语核心

这是整个项目最关键的模块：它决定“哪些写法算同一个专业名词”。

### 1.1 文本与键

| API | 说明 |
|---|---|
| `clean_text(text)` | 去 Markdown/HTML、统一 Unicode、压缩空白，得到展示文本 |
| `normalize_key(text)` | 仅保留小写字母数字的键；**会丢掉中文**，只用于拉丁术语比较 |
| `compact_key(text)` | 小写字母数字键，用于合并普通名称 |
| `singular_key(key)` | 去掉英文复数结尾，用于单复数合并 |

**注意**：中文建议标签的检索键不能用 `normalize_key`，页面用保留 CJK 的独立 `search_key`。

### 1.2 化学式与身份

| API | 说明 |
|---|---|
| `formula_identity(text)` | 化学式身份：大小写不敏感，保留化学计量与相；不是化学式返回 `None` |
| `looks_like_formula(text)` | 便捷判断 |
| `identity_key(label, type, expansion)` | 跨论文合并用的身份键：化学式 → `formula:`；缩写 → 展开；否则 `name:` |
| `concept_id_for(type, identity)` | 由类型 + 身份生成稳定 `c-<sha1>` |

规则要点：

- `AgBiS2`、`agbis2`、`AgBiS₂` 视为同一化学式。
- `α-FAPbI3` 与 `δ-FAPbI3` **不合并**：相前缀保留。
- 缩写按论文作用域：同一篇内 `ALD` 展开为 `atomic layer deposition` 才合并；跨论文不强行合并。

### 1.3 类型与粒度

| API | 说明 |
|---|---|
| `is_abbreviation(text)` | 短全大写（TMDCs、APD、STED） |
| `is_instance_label(label)` | 论文内实验实例（device A、sample 3）而非专业概念 |
| `is_symbol_fragment(label)` | 单字母、罗马数字、公式解析残片 |
| `label_quality(label)` | `clean` / `fragment` / `instrument` / `symbol` |
| `classify_type(label)` | 中心词规则判定 12 类，返回 `(type, rule)` |
| `resolve_type(label, observed_types, expansion)` | 融合 v2 观察类型与规则类型，输出 `TypeResolution`（含冲突状态） |
| `split_attribute_phrase(label)` | 把“SiC film”拆成 head=`SiC` + 修饰语，返回 `PhraseSplit` |

### 1.4 别名

| API | 说明 |
|---|---|
| `extract_parenthetical_aliases(text)` | 从正文挖 `full name (ABBR)` 对 |
| `abbreviation_expansions(aliases)` | 单篇内 `ABBR → 展开`，第一次定义优先 |

### 1.5 关系语义

| API | 说明 |
|---|---|
| `relation_family(predicate)` | 谓词 → 9 个族：effect/process/dependency/characterization/taxonomy/application/composition/structure/phase_transition/other |
| `relation_direction_check(subject_type, predicate, object_type)` | 因果方向检查，返回 `DirectionCheck(ok, reason, reverse)` |
| `evidence_qualifiers(evidence)` | 从证据句读 polarity（positive/negative）与 modality（asserted/hedged） |

### 1.6 概念注册表

| 类/方法 | 说明 |
|---|---|
| `ConceptRecord` | 一个概念：`concept_id`、规范名、类型、身份、别名、表面形式、论文、提及数、质量、中文标签、复核状态 |
| `ConceptRegistry.add(paper_id, label, v2_types, expansion, alias, evidence, review_status)` | 注册一个写法，返回合并后的 `ConceptRecord` |
| `ConceptRegistry.find_label(label, paper_id=None)` | 查概念（可按论文作用域） |
| `ConceptRegistry.to_list()` | 导出概念层列表 |

**注意**：`add` 内部按 `identity_key` 合并；别名会记录来源论文和证据句，便于审计“为什么合并”。

## 2. `entity_standardization.py` — 实体与谓词标准化

| API | 说明 |
|---|---|
| `standardize_entities(triples, config)` | 跨块合并实体：大小写、停用词、复数、词子集（可配）；可选 LLM 消歧 |
| `normalize_predicates(triples)` | 谓词大小写/空白/时态归一 |
| `limit_predicate_length(predicate)` | 限制谓词词数，去掉尾部停用词 |
| `infer_relationships(triples, config)` | 按配置做分类/词法/桥接/枢纽推断；materials 下全部关闭 |
| `taxonomy_predicates(triples)` | 识别可做分类推断的谓词 |

**注意**：materials profile 的 `apply_profile_overrides` 会把推断全部关掉，`infer_relationships` 实际不做任何事。

## 3. `postprocess/` — 观测与条件

### `conditions.py`

| API | 说明 |
|---|---|
| `normalize_conditions(conditions)` | 温度/时间/气氛等条件归一 |
| `backfill_conditions(triples)` | 模型没给条件时，从证据句回填 |
| `annotate_condition_status(triples)` | 标记 explicit/inferred/missing |
| `detect_value_type(triples)` | 数值类型：measured/reported/derived |
| `detect_source_study(triples)` | 标记转引（综述里的“某研究报道…”） |
| `dedupe_observations(triples)` | 同一论文内相同样品/属性/值/单位/条件去重 |
| `postprocess(triples)` | 串起以上步骤并返回计数 |

### `quantities.py`

| API | 说明 |
|---|---|
| `canon_unit(unit)` | 单位规范化（eV、%、nm…） |
| `parse_quantity(text)` | 字符串 → 数值记录；非数值返回 None |
| `build_observations(triples, paper_id)` | 数值属性边 → `obs-` 观测节点 + `has measurement` 边 |
| `count_by_origin(triples)` | 统计 extracted/inferred/observation/ontology |
| `predicate_stats(triples)` | 谓词分布 |
| `collect_parse_failures(triples)` | 看起来是测量但数值解析失败的边 |

## 4. `retrieval.py` — v3 图索引

`KnowledgeGraphIndex.load(directory)` 读入 `concepts/relations/alias_index/instances/observations`。

| 方法 | 说明 |
|---|---|
| `search(query, limit=10, include_noisy=False, type_filter=None)` | 术语/别名/化学式/中文标签的排序检索 |
| `resolve(label)` | 最佳概念（search 第一条） |
| `browse(concept_id, limit=20)` | 概念卡：别名、出边、入边、样品、观测 |
| `relations_between(subject_id, object_id)` | 两概念间的关系 |
| `find_relation(subject_label, predicate_any, object_labels, families)` | 按主语 + 谓词 + 宾语集合查关系（验收用例用） |
| `view(relation)` | 稳定字段的关系视图 |
| `stats()` / `describe(concept_id)` | 统计 / 一句话描述 |

**注意**：索引是内存结构，适合单机脚本与服务；全量 39,400 条关系加载约数百毫秒。

## 5. `query.py` — 图问答

| API | 说明 |
|---|---|
| `GraphIndex` | 三元组列表的轻量索引 |
| `match_entities(question, entities)` | 整名优先、再按共享实词匹配问题中的实体 |
| `shortest_path(graph, a, b)` | 无向最短路径 |
| `retrieve_subgraph(...)` | 以种子实体为中心取 1–2 跳子图，优先种子间路径 |
| `format_facts(triples)` | 事实编号文本 |
| `parse_answer(reply)` | 拆出答案与引用的事实编号 |
| `GraphChat` | 组织“检索子图 → 提示词 → LLM → 带引用回答” |
| `main()` | `graph-chat` CLI |

## 6. `server.py` — 可选 Web 界面

| 路由/类 | 说明 |

## 7. `visualization.py` — 通用图谱页

| API | 说明 |
|---|---|
| `display_name(name)` | 全小写名称首字母大写 |
| `entity_types(triples, allowed)` | 每个节点按多数票决定实体类型 |
| `build_graph_data(...)` | 纯数据：节点、边、选项、元数据；不写文件 |
| `render_html(graph_data, library_dir, page_dir)` | Jinja 渲染页面 |
| `ensure_library(library_dir, page_dir)` | 复制 vis-network 静态资源 |
| `visualize_knowledge_graph(...)` / `render_knowledge_graph(...)` | 高层入口：构图 + 渲染 + 统计 |
| `sample_data_visualization(...)` | 内置样例，用于 `--test` |

**构图细节**：networkx 计算度/介数/特征向量中心性 → Louvain 社区 → 社区配色与命名 → 节点大小按中心性 → 可选平行边折叠与推断边显示。

## 8. `exports.py` — 通用导出

| API | 说明 |
|---|---|
| `export_graph(triples, output_html, formats, config)` | 按格式写文件，返回路径 |
| `write_csv(triples, path)` | 扁平 CSV |
| `write_graphml(triples, path)` | Gephi/yEd/Cytoscape；节点带类型/社区/度数，边带出处 |
| `write_cypher(triples, path)` | Neo4j 幂等 `MERGE` 脚本；实体一个 label，谓词一个关系类型 |
| `parse_formats(text)` | `"graphml,cypher"` → 校验后的列表 |

**注意**：材料项目的交付三元组不走这里，而由 `article/export_materials_graph.py` 生成固定 18 列 CSV；`exports.py` 服务于通用 `generate-graph`。
