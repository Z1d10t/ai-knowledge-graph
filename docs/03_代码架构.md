# 03 代码架构

## 1. 分层

```
入口层    generate-graph / graph-chat / graph-serve / 脚本
配置层    config.py + profiles.py
抽取层    main.py → text_utils.py → llm.py + prompts/
后处理层  entity_standardization.py + postprocess/
术语层    terminology.py（概念、别名、类型、方向）
检索层    retrieval.py（v3 索引）/ query.py（问答）
展示层    visualization.py + templates/（通用页、材料页）
交付层    article/export_materials_graph.py + delivery/
评估层    evaluation/*.py
```

## 2. 单篇/多篇论文的抽取调用链

```
main.main()
 ├─ load_config()                          # TOML + 默认值 + 校验
 ├─ apply_profile_overrides()              # materials: 关闭推断
 ├─ read_documents(--input)                # md/txt/pdf/docx → (name, text)
 ├─ process_documents()
 │   ├─ chunk_text()                       # 按句切块，带 overlap
 │   ├─ ThreadPoolExecutor(concurrency)
 │   │   └─ process_with_llm()
 │   │       ├─ main_prompt_pair()         # system + user 提示词
 │   │       ├─ LLMClient.complete()       # 请求、重试、缓存、截断检测
 │   │       ├─ extract_json_from_text()   # 从回复里取 JSON
 │   │       └─ normalize_triple()         # 字段校验、类型、证据句
 │   ├─ standardize_entities()             # 跨块实体合并
 │   ├─ infer_relationships()              # 按配置做可选推断
 │   ├─ build_observations()               # 数值属性 → 观测节点（materials）
 │   └─ conditions.postprocess()           # 条件、数值类型、来源研究
 ├─ make_community_namer()                 # 可选：LLM 给社区起名
 ├─ render_knowledge_graph()               # Jinja 页面 + vis-network
 └─ export_graph()                         # json/csv/graphml/cypher
```

## 3. 285 篇语料 → 交付页面的调用链

```
article/extract_corpus.py                 # 逐篇抽取（DeepSeek / 任意兼容端点）
  → evaluation/full_v2/kg_output/enriched/*.json
evaluation/normalize_v3.py                # v2 → v3 概念层
  → evaluation/full_v3_delivery/*.jsonl
article/export_materials_graph.py         # v3 → 交付包
  ├─ load_graph()                          # 读入并校验
  ├─ build_nodes()                         # 概念 + 实例 → 节点
  ├─ layout_communities()                  # 类型区域 + Louvain 社区布局
  ├─ build_triples()                       # 关系 → 三元组行
  ├─ build_evidence()                      # 每条关系 → 原文引文/行号
  ├─ write_browser_data()                  # data/*.json、证据分片
  ├─ write_page()                          # 模板 + vis-network 复制
  ├─ render_overview_png()                 # Pillow 占位图（可被页面截图替换）
  └─ verify()                              # 15 项检查
  → delivery/materials_kg_final/
```

## 5. 关键数据契约

### 抽取三元组（v2）

```python
{
  "subject": str, "predicate": str, "object": str,
  "subject_type": str, "object_type": str,
  "source": str,              # 证据句
  "chunk": int,
  "value"/"unit"/"conditions"/"sample_id": ...,  # materials 扩展字段
}
```

### 规范关系（v3）

```python
{
  "relation_id": "r-...", "paper_id": str,
  "subject_id": "c-..."/"i-...", "object_id": ...,
  "subject_label"/"object_label": str,
  "predicate": str, "raw_predicate": str, "family": str,
  "evidence": str, "evidence_line": int|None,
  "direction_ok": bool, "polarity": str, "modality": str,
  "review_status": str, "source": str,
}
```

### 页面节点（nodes.json）

```python
[id, label, type_idx, quality, paper_count, mention_count, degree,
 in_graph, x, y, community, zh, aliases, surface_forms, paper_id]
```

## 7. 依赖关系

- 核心依赖：`jinja2`、`networkx`、`requests`。
- 页面：浏览器端 vis-network（仓库内 `templates/vendor/`，不访问 CDN）。
- 交付导出：标准库 + Pillow（生成占位 PNG；页面截图可替换）。
- 规范化：标准库 + networkx（Louvain 社区）。
- 测试：pytest；服务器测试在缺少 FastAPI 时自动跳过。
